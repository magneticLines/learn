CPU 1214C · 博图 V16 · WinCC V7.5 · NetToPLCsim

1214C 本机联调：博图程序连 WinCC 画面

没有真实 PLC，博图 V16 写的 1214C 程序、WinCC V7.5 做的画面都在同一台电脑上。按这一页从上到下做，每一步都有“怎么确认做对了”，就能让 WinCC 画面读写仿真 PLC 里的数据。

这套环境里每个软件的角色

博图 V16写程序、下载编写 1214C 的 PLC 程序，编译后下载到仿真 PLC。
S7-PLCSIM V16假装成一台 1214C西门子官方的 PLC 仿真器，在电脑里运行你的 PLC 程序。和博图是两个产品，要单独安装。
NetToPLCsim翻译 / 转发免费第三方工具，在本机网卡上开 102 端口，把 WinCC 的请求转给 PLCSIM。
WinCC V7.5上位机画面独立软件，有自己的项目，不导入博图。按 IP 去连 NetToPLCsim，读写 PLC 变量并显示在画面上。

原理

为什么中间要多一个 NetToPLCsim

PLCSIM 不对外开放

PLCSIM 只和博图内部通信，没有网络接口，WinCC 按 IP 找不到它。能对外开放网络的 PLCSIM Advanced 又只支持 S7-1500，不支持 1214C。NetToPLCsim 正好填这个空：它在本机网卡上监听 S7 通信端口 TCP 102，把 WinCC 发来的请求转给 PLCSIM，WinCC 就以为自己连上了一台真实 PLC。

代价：只能用绝对地址

NetToPLCsim 只转发经典 S7 协议的 PUT/GET 读写，也就是按 DB1,DBX0.0 这种“块号 + 字节偏移”访问。所以：

  • WinCC 要用 SIMATIC S7 Protocol Suite 驱动，不能用 SIMATIC S7-1200, S7-1500 Channel。后者按变量名（符号）访问，走的是新一代协议，NetToPLCsim 不支持。
  • WinCC 的“从 AS 读取符号”用不了，变量要按博图 DB 的偏移量手工建（可以用 Excel 批量做）。
  • 博图里 PLC 要勾 PUT/GET，给 WinCC 用的 DB 要取消“优化的块访问”。

连真实 1214C 时用 S7-1200, S7-1500 Channel 是对的。它只是不适合这套仿真环境。

记住两个 IP：192.168.0.1 是 PLC 自己的 IP，只在博图和 NetToPLCsim 里用；192.168.0.10 是环回网卡的 IP，WinCC 连的是它。
准备阶段

软件准备：先确认四个软件都装好

这四个软件是分开安装的。装了博图不代表就有 PLCSIM，NetToPLCsim 更不在任何西门子安装包里。开始联调前，先对照下表把缺的补齐。

软件作用从哪来费用
博图 STEP 7 V16写 PLC 程序、下载西门子官网，或学校 / 公司提供的安装包收费，有试用授权
S7-PLCSIM V16仿真 PLC，运行程序单独下载，西门子官网收费，有试用授权
WinCC V7.5做上位机画面单独下载，西门子官网收费，有试用授权
NetToPLCsim把 PLCSIM 开放到网络单独下载，SourceForge免费开源
PLCSIM 是什么

S7-PLCSIM 是西门子官方的 PLC 仿真软件，在电脑里“假装”成一台真实 PLC。博图把程序下载给它，它就像真 PLC 一样执行，你可以在博图里在线监视、修改变量。它没有物理输入输出，也不对外开放网络，所以本方案要靠 NetToPLCsim 把它接到网络上。

容易混淆的版本搭配软件支持的 PLC网络接口本方案是否需要
S7-PLCSIM V5.x经典 STEP 7 V5.xS7-300 / 400无不需要
S7-PLCSIM V16博图 V16S7-1200 / 1500无需要
S7-PLCSIM Advanced V3.0博图 V16仅 S7-1500有仅备选方案
版本必须一致：PLCSIM 的版本号要和博图完全相同。博图 V16 只能配 PLCSIM V16，装成 V15 或 V17 都用不了。

  1. 检查是否已经装好

    很多博图安装包里自带 PLCSIM 的安装文件夹，先确认一下，满足任一条就说明已经装好：

    • 开始菜单的 Siemens Automation 文件夹里有 S7-PLCSIM V16、WinCC。
    • 博图里选中 PLC，工具栏的 开始仿真 按钮可以点。
    • 控制面板›程序和功能 里能看到 SIMATIC S7-PLCSIM V16。

  2. 下载西门子软件

    • 如果博图是学校或公司给的，先找他们要完整安装包，PLCSIM 和 WinCC 通常都在里面，比自己下载省事。
    • 自己下载的话，打开西门子工业支持网站 support.industry.siemens.com（SiePortal），注册账号并登录。注册免费，但审核可能要几小时到一两天。
    • 搜索 S7-PLCSIM V16 Trial、WinCC V7.5 Trial，下载试用版。
    • 下载下来通常是多个压缩分卷，放到同一个文件夹，只解压第一个，后面的分卷会自动合并。
    官网页面经常改版，具体入口以搜索结果为准。

  3. 下载 NetToPLCsim

    在 SourceForge 搜索 NetToPLCsim，从官方项目页下载最新版。它是绿色软件，解压就能用，不需要安装。

    只从官方项目页下载：不要用网盘或软件站的转载包，可能被捆绑了其他程序。它会监听端口、停系统服务，杀毒软件可能误报，确认来源后加入信任即可。

  4. 按顺序安装

    建议顺序：WinCC V7.5 → 博图 STEP 7 V16 → S7-PLCSIM V16 → 解压 NetToPLCsim。

    • PLCSIM 要挂到博图里才能用，必须先装博图再装 PLCSIM，反了博图可能识别不到。
    • WinCC 和博图会共用一部分西门子底层组件。装之前可以用西门子官网的 Compatibility Tool 确认这两个版本能装在同一台电脑上。
    • 安装前关闭杀毒软件，安装路径不要有中文。
    • 提示重启就重启。西门子软件经常要重启好几次，跳过重启是安装报错的常见原因。

  5. 确认授权

    打开开始菜单里的 Automation License Manager，确认博图、PLCSIM、WinCC 都有授权。试用版第一次运行时会提示激活试用授权，一般能用 21 天。没有授权时 PLCSIM 无法启动，WinCC 会以演示模式运行，一段时间后自动退出。

  6. 确认 1214C 的固件版本

    PLCSIM 只能仿真固件 V4.0 及以上的 S7-1200。在博图设备组态里选中 CPU，查看 属性›常规›目录信息 中的固件版本。版本太老的话，右键 CPU → 更改设备，换成同型号的 V4.x 固件。

第一阶段

博图 V16：准备 PLC 程序并启动仿真

这一阶段全部在博图里操作。

  1. 打开仿真支持

    项目树里右键 项目名（最顶上那一行）→ 属性 → 保护 选项卡，勾选 块编译时支持仿真 → 确定。

    不勾的话，下载到 PLCSIM 时会提示“不支持仿真”。

  2. 放开 PLC 的访问权限

    项目树里双击 PLC_1 [CPU 1214C]›设备组态，单击画面里的 CPU，下方 属性›常规›防护与安全：

    • 访问级别：选“完全访问权限（无任何保护）”。
    • 连接机制：勾选 允许来自远程对象的 PUT/GET 通信访问。
    为什么必须勾 PUT/GET

    WinCC 经过 NetToPLCsim 读写数据，用的就是 PUT（写）/ GET（读）这两种请求。1214C 默认拒绝外部的 PUT/GET，不勾的话连接能建立，但读到的值一直是 0，写也写不进去。

  3. 设定 PLC 的 IP

    还是在 CPU 属性里：常规›PROFINET 接口 [X1]›以太网地址，IP 设为 192.168.0.1，子网掩码 255.255.255.0。

    NetToPLCsim 会按这个 IP 找到仿真 PLC。WinCC 不直接用这个 IP。

  4. 找到（或新建）给 WinCC 用的 DB

    DB（数据块）是 PLC 程序的一部分，只在博图里有。WinCC 里看不到 DB，它只按 DB1,DBW2 这样的地址去 PLC 里读写。
    • 项目树 → PLC_1›程序块，看有没有 DB。已有的话，名字后面方括号里的就是编号，比如 DB [DB1]。
    • 没有的话：双击 添加新块 → 左边选 数据块 (DB) → 名称填 HMI_Data → 类型选 全局 DB → 确定。把要在画面上显示和操作的变量都放进去。

  5. 取消“优化的块访问”，并固定 DB 编号

    1. 右键这个 DB → 属性。
    2. 左边选 属性（不是“常规”）→ 取消勾选“优化的块访问”。
    3. 左边选 常规 → 编号 从“自动”改成 手动，记下编号（例如 1）→ 确定。
    4. 右键 DB → 编译。
    5. 双击打开 DB，表格里多出一列 偏移量，每个变量都有了 0.0、2.0 这样的值。
    为什么必须取消优化

    “优化的块访问”打开时，PLC 会自行安排变量的存储位置，变量没有固定的字节偏移量，DB1,DBX0.0 这样的地址也就不存在。取消后变量按声明顺序依次排列，每个变量都有确定的偏移量。

    为什么要把编号改成手动

    WinCC 的地址里写死了 DB 编号。编号默认自动分配，删掉重建或者从别的项目复制 DB 时可能会变，一变 WinCC 里的地址就全部失效。

    看不到偏移量列：确认已取消优化并编译过；还看不到的话，在列标题上右键，把“偏移量”列显示出来。

  6. 启动 PLCSIM：选中 PLC → 开始仿真

    “下载”是什么意思

    博图里写的程序只存在电脑上的项目文件里，PLC 并不知道。“下载”就是把项目内容传进 PLC（这里是 PLCSIM）的存储器，PLC 才能运行它。下载的内容分两部分：硬件配置（IP 地址、PUT/GET 权限、访问级别等设置）和软件（OB、FC、DB 等程序块）。

    • 项目树里单击选中 PLC_1 [CPU 1214C] 这一行，不用展开。
    • 点工具栏的 开始仿真（电脑屏幕图标），或者走菜单 在线›仿真›启动。
    • 第一次点时会提示“启动仿真将禁用所有其他在线接口”，点 确定。
    • 随后会弹出一个 PLCSIM 小窗口（带 RUN / STOP 指示灯），紧接着弹出下载相关的对话框。
    按钮是灰的或点了没反应：检查 PLCSIM 是否已安装、版本是否为 V16，以及选中的是不是 PLC 那一行。

  7. 在“扩展下载到设备”里找到仿真 PLC

    没弹出这个对话框、直接进了“下载预览”也是正常的：博图记住了之前用过的连接路径，会自动跳过这一步，直接看下一步即可。
    字段选什么
    PG/PC 接口的类型PN/IE
    PG/PC 接口PLCSIM，下拉框里名字带 PLCSIM 的那一项
    接口/子网的连接PN/IE_1 或“插槽 1 X1 处的方向”，保持默认即可
    第一个网关不填

    点 开始搜索，列表里出现 CPU 1214C、地址 192.168.0.1 的设备后，选中它，点 下载。

    为什么接口选 PLCSIM

    博图和 PLCSIM 之间走的是一条内部的虚拟通道。选成真实网卡的话，博图会去网线上找真 PLC，自然搜不到。

    搜不到设备：确认 PLCSIM 窗口已弹出、接口选的是 PLCSIM 而不是有线或无线网卡，再勾选“显示所有兼容的设备”重新搜索。

  8. 下载预览：硬件配置和软件一起下

    博图会先编译，再弹出 下载预览，最右边“动作”列逐项确认：

    项目动作选什么
    停止模块全部停止，下载时 PLC 要先停下来
    设备组态 / 硬件配置下载到设备
    软件下载到设备 或 一致性下载

    没有红色 ❌ 后点 装载。

    必须连硬件配置一起下：IP、PUT/GET、访问级别都存在硬件配置里，不在程序里。只下软件的话这些设置不生效，WinCC 能连上但读不到值。不确定上次有没有下硬件配置时，右键 PLC → 下载到设备›硬件和软件（仅更改） 再下一次，没有副作用。
    出现红色 ❌ 时点开看说明。常见的是“不支持仿真”：回到本阶段第 01 步勾选“块编译时支持仿真”，重新编译后再下载。

  9. 下载结果：启动 PLC，确认进入 RUN

    • 下载结果 窗口里勾选 全部启动，点 完成，PLC 会自动切到 RUN。
    • 看 PLCSIM 小窗口：RUN 灯变绿就成功了；还是 STOP 的话点窗口上的 RUN 按钮手动切换。
    • ERROR 红灯亮：选中 PLC → 转到在线 → 在线和诊断›诊断缓冲区，看里面写的出错原因。
    • 再确认一次：选中 PLC → 转到在线，项目树里各项后面出现绿色对勾，说明博图项目和仿真 PLC 里的内容一致；看完点 断开在线。
    以后改了程序，PLCSIM 还开着的话不用重新“开始仿真”，选中 PLC 点工具栏 下载到设备，同样走下载预览和下载结果两步即可。改了 DB 变量后偏移量会变，WinCC 里的地址也要跟着改。
第二阶段

添加一块环回网卡，给 NetToPLCsim 用

为什么不用真实网卡

NetToPLCsim 需要一个本机 IP 来监听。环回网卡是 Windows 自带的一块虚拟网卡，只存在于系统里，不受网线是否插着、Wi-Fi 换没换、公司网络 IP 是多少的影响，联调最稳定。

  1. 安装环回网卡

    1. Win + R 输入 hdwwiz 回车，打开“添加硬件向导”→ 下一步。
    2. 选 安装我手动从列表选择的硬件（高级） → 下一步。
    3. 选 网络适配器 → 下一步。
    4. 左边厂商选 Microsoft，右边型号选 Microsoft KM-TEST 环回适配器（英文系统叫 Microsoft KM-TEST Loopback Adapter）→ 下一步 → 下一步 → 完成。

  2. 给它设静态 IP

    1. Win + R 输入 ncpa.cpl 回车，打开“网络连接”。
    2. 找到新出现的网卡（名字一般是“以太网 2”之类，下面小字写着 Microsoft KM-TEST 环回适配器）。建议右键 → 重命名 为 Loopback。
    3. 右键 → 属性 → 双击 Internet 协议版本 4 (TCP/IPv4)。
    4. 选“使用下面的 IP 地址”：IP 192.168.0.10，掩码 255.255.255.0，网关和 DNS 留空 → 确定。

  3. 检查网段冲突

    Win + R → cmd，输入 ipconfig，看每块网卡的 IPv4 地址：

    • 只有环回网卡是 192.168.0.x：正常。
    • Wi-Fi 或有线网卡也在 192.168.0.x：冲突，电脑发数据时不知道走哪块网卡，连接会时有时无。
    有冲突就整体换网段：环回网卡改成 192.168.100.10，博图里 PLC 改为 192.168.100.1 并连硬件配置一起重新下载，后面 NetToPLCsim 和 WinCC 里的地址也都换成新的。

  4. 确认网卡生效

    ping 192.168.0.10

    看到“来自 192.168.0.10 的回复”就说明环回网卡好了。

第三阶段

配置 NetToPLCsim

前提：PLCSIM 已经是 RUN。NetToPLCsim 启动时要找正在运行的 PLCSIM，顺序反了会找不到。

  1. 以管理员身份运行

    用准备阶段下载的 NetToPLCsim 最新版（它对 PLCSIM V16 的支持取决于自身版本）。解压后右键 NetToPLCsim.exe → 以管理员身份运行。

  2. 让出 102 端口

    启动时如果提示 102 端口被占用，并询问是否停止 S7DOS Help Service（有的版本叫 IEPG Help Service），选 是。这个西门子服务默认占着本机的 102 端口，不停掉 NetToPLCsim 就无法监听。

    停掉这个服务只影响本次开机。电脑重启后它会自动恢复，下次联调时 NetToPLCsim 会再问一次。

  3. 添加站点

    点 Add，填写：

    字段填什么含义
    NamePLC_1214C随便起，只是个标签
    Network IP Address192.168.0.10点旁边的按钮选环回网卡。WinCC 要连的就是这个地址
    Plcsim IP Address192.168.0.1博图里 PLC 的 IP，可以点按钮从正在运行的 PLCSIM 中选
    Rack / Slot0 / 1S7-1200 固定是机架 0、插槽 1

  4. 启动转发

    点 Start Server，站点状态显示 running 即可。

  5. 验证 102 端口在监听

    PowerShell 里执行（Windows 自带，只输出 True / False）：

    Test-NetConnection 192.168.0.10 -Port 102 -InformationLevel Quiet
    • True：NetToPLCsim 在工作，这一段没问题。
    • False：NetToPLCsim 没在监听，回到第 01～04 步；ping 也不通的话，检查环回网卡是否被禁用。

    也可以用 telnet 192.168.0.10 102，窗口变成一片空白就是通了（按 Ctrl + ] 再输入 quit 退出）。Windows 11 默认没装 telnet，要在 optionalfeatures 里勾选“Telnet 客户端”。

    失败时两种方法都要等十几秒超时，成功则几乎立刻出结果。
第四阶段

WinCC V7.5：打开项目、建驱动和连接

WinCC 项目不用导入博图

WinCC V7.5（经典 WinCC）和博图里的 WinCC Basic / Advanced / Professional 是两个东西。它有自己独立的项目（.mcp 文件），只通过网络和 PLC 通信，两边唯一的约定是变量地址。

  1. 打开项目，修正计算机名

    项目是别的电脑做的、或者你改过电脑名时，激活会报“组态的服务器不可用，请更正您输入的服务器名称”。打开项目后先做这一步：

    1. cmd 里执行 echo %COMPUTERNAME%，记下电脑名（用它而不是 hostname，WinCC 用的是这个最长 15 位的名字）。
    2. WinCC 项目管理器左边单击 计算机，右边那台计算机右键 → 属性，计算机名称 改成刚才的名字，一个字符都不能差。
    3. 文件›关闭，再 文件›打开 同一个 .mcp。有时要关闭重开两次才生效。
    4. 顺便确认项目类型：左边树最顶上的项目名右键 → 属性 → 类型应为 单用户项目。
    项目文件夹的路径里不要有中文和空格。

  2. 当前 Windows 用户加入 SIMATIC HMI 组

    只有 SIMATIC HMI 组里的用户才能访问 WinCC 服务器，不在组里也会报“服务器不可用”。

    1. Win + R → lusrmgr.msc → 左边 组 → 双击 SIMATIC HMI。
    2. 成员里没有当前用户（cmd 里 whoami 查看）就点 添加 加进去。
    3. 注销 Windows 重新登录，权限才生效。

  3. 把访问点 CP-TCPIP 指向环回网卡

    WinCC 不直接选网卡，而是通过“访问点”间接指向网卡。

    1. 控制面板（右上角查看方式改成“大图标”）→ 设置 PG/PC 接口。
    2. 上方“应用程序访问点”选 CP-TCPIP。下拉框里没有的话，选“添加/删除”新建一个叫 CP-TCPIP 的。
    3. 下方列表选 Microsoft KM-TEST 环回适配器.TCPIP.1 → 确定。
    列表里长得很像的选项协议能不能用
    …环回适配器.TCPIP.1TCP/IP选这个
    …环回适配器.TCPIP.Auto.1TCP/IP（自动获取 IP）一般也行
    …环回适配器.ISO.1ISO，按 MAC 地址通信，不走 TCP不能用
    列表里一个带“环回适配器”的都没有：先重启电脑，西门子通信组件开机时才重新扫描网卡。还没有的话，点窗口里的“选择…”按钮安装 TCP/IP 接口。

  4. 添加 SIMATIC S7 Protocol Suite 驱动

    WinCC 项目管理器 → 右键 变量管理 → 添加新的驱动程序 → 选 SIMATIC S7 Protocol Suite。

    展开后下面有 MPI、PROFIBUS、Industrial Ethernet、TCP/IP 等好几个通道单元。本方案只用 TCP/IP：

    通道单元怎么通信能不能连 NetToPLCsim
    TCP/IP按 IP 地址，走 TCP能
    Industrial Ethernet按 MAC 地址，不经过 TCP不能
    MPI / PROFIBUS专用总线不能

  5. 确认通道单元的逻辑设备名称

    右键 TCP/IP 通道单元 → 系统参数 → 单元 页，逻辑设备名称应为 CP-TCPIP，和上面的访问点名字一字不差。

  6. 新建连接

    右键 TCP/IP → 新建连接，命名 PLC_1214C（名字只是标签，随便起，尽量只用字母、数字和下划线）→ 右键这个连接 → 连接参数：

    • IP 地址：192.168.0.10，填 NetToPLCsim 监听的地址，不是 PLC 的 192.168.0.1。
    • 机架号 0，插槽号 1。
第五阶段

按偏移量建变量

偏移量在博图里看，地址在 WinCC 里填，两者是同一个位置的两种写法。WinCC 里没有“偏移量”这一列，只有“地址”。
先试几个，再批量：先建 3～4 个有代表性的变量（1 个 Bool、1 个 Int、1 个 Real，再加 1 个 DB 里比较靠后的），走完第六阶段和验证，确认连通了再批量建。

  1. 把偏移量换算成 WinCC 地址

    规则：偏移量小数点前是字节号，小数点后是位号（只有 Bool 才用）；数据类型决定按位 / 字节 / 字 / 双字读。

    博图类型长度例：偏移量WinCC 数据类型WinCC 地址
    Bool1 位0.1二进制变量DB1,DBX0.1
    Byte1 字节1.0无符号 8 位数DB1,DBB1
    Int2 字节2.0有符号 16 位数DB1,DBW2
    Word2 字节2.0无符号 16 位数DB1,DBW2
    DInt4 字节4.0有符号 32 位数DB1,DBD4
    Real4 字节4.0浮点数 32 位 IEEE 754DB1,DBD4

    M 区、I/Q 区不需要 DB，也不受“优化”影响，直接写 M10.0、MW20、I0.0、Q1.1（有的语言设置下输入 / 输出显示成德文的 E / A，意思一样）。

    最常见的错误：Real 建成了整数类型。地址对了，但 25.5 会显示成 1103888384 这种离谱数字。

  2. 在 WinCC 里填一个变量

    1. 变量管理里单击选中连接 PLC_1214C，右边是这个连接下的变量表。
    2. 最下面空行新建变量：先填 名称，再选 数据类型（先选类型，地址窗口里可选的寻址方式才对）。
    3. 单击这一行的 地址 单元格，点右边出现的 … 按钮（有的版本要双击），打开地址属性窗口：
    窗口里的字段怎么填例：Speed，Int，偏移量 2.0
    数据区域DBDB
    DB 号博图里 DB 的编号1
    寻址Bool→位，Byte→字节，Int / Word→字，Real / DInt→双字字
    起始地址（DBW / DBD / DBX 后面的数）偏移量小数点前的数2
    位偏移量小数点后的数，只有 Bool 才填不填

    确定后地址显示为 DB1,DBW2。找不到 … 按钮：确认选中的是连接而不是“内部变量”（内部变量没有地址栏），地址列在表格靠右，可能要往右拖滚动条。

  3. 数组和 Struct：拆成一个个变量

    S7 Protocol Suite 里没有数组变量、结构体变量，每个元素 / 成员各建一个。博图 DB 里点数组或 Struct 前面的 ▶ 展开，就能看到每个成员的偏移量。自己算的话按这几条规则：

    • 数组、Struct 一定从偶数字节开始，Struct 总长度凑成偶数。
    • 数组元素紧挨着排：元素字节 = 数组起始 + (下标 − 下限) × 元素长度。注意 Array[1..5] 从 1 开始。
    • Bool 数组按位挤在一起：第 k 个元素在 起始 + k÷8 字节的 k mod 8 位。
    • Struct 内部：Bool 按位挤在一起，Int / Real 从偶数字节开始。
    例：Motors : Array[1..3] of "Motor_T" 从 22.0 开始、每个 8 字节，则 Motors[2].Speed（成员内偏移 2）= 22 + 8 + 2 = DB1,DBW32。WinCC 变量名用 Motors_2_Speed，不要带方括号。

    同一种 Struct 重复很多次时，可以用 WinCC 的 结构类型：变量管理 → 结构类型 → 新建，成员填相对偏移；之后每个实例只建一个结构变量、给起始地址，WinCC 自动展开出各成员。

  4. 迁移已有项目：保持原变量名，换到新连接下

    如果手上是别人做好的完整 WinCC 项目，画面里的按钮、I/O 域都绑定着原来的变量。原项目通常用 S7-1200, S7-1500 Channel（按符号访问，比如 "DB".HMI按键.启动），连不了 NetToPLCsim。做法是让新连接下的变量顶替原名，画面一个都不用改：

    1. 查按钮用的变量：图形编辑器里右键按钮 → 属性 → 事件 → 鼠标，双击蓝色闪电。直接连接看“目标”里的变量名；C 动作找 SetTagBit("变量名", 1)；VBS 找 HMIRuntime.Tags("变量名")。I/O 域在 属性›输出/输入›输出值 旁边看。
    2. 原变量改名：旧驱动下的变量改名加 _old（或删除）。WinCC 不允许重名，不先处理新变量建不了。
    3. 建同名新变量：在 PLC_1214C 下新建变量，名字和原名一模一样，地址按符号去博图查偏移量："DB".HMI按键.启动 → 打开 DB → 展开 HMI按键 → 启动的偏移量 48.0 → DB1,DBX48.0。原地址本来就是 %M10.0 这种绝对地址的，去掉 % 照抄。
    4. 检查：WinCC 项目管理器里的 交叉索引 刷新一次，确认画面引用的变量都能在新连接下找到。
    5. 全部切换并测试通过后，把旧驱动整个删掉，免得它每次激活都尝试去连原来的 PLC。
    原始项目已提交在 git 里，改坏了直接用 git 恢复到最初版本即可，不用另外复制备份。
    本仓库的“灌装”项目已经整理好了一张对照表：other/wincc-tag-mapping.csv（WinCC 变量名 → 新地址），可以直接参照。用之前在博图里抽查 2～3 个偏移量是否一致。

  5. 变量多时用 Excel 批量生成

    1. 博图里打开 DB（已编译），选中所有行 Ctrl + C，粘贴到 Excel，只留“名称、数据类型、偏移量”三列（A、B、C）。
    2. WinCC 里先手工建一个 Bool、一个 Int、一个 Real 当样板，看你的软件里“数据类型”和“地址”列实际显示成什么格式。
    3. Excel 加一列地址公式（DB 号按实际改）：
    =IF(B2="Bool","DB1,DBX"&TEXT(C2,"0.0"),IF(B2="Byte","DB1,DBB"&INT(C2),IF(OR(B2="Int",B2="Word"),"DB1,DBW"&INT(C2),IF(OR(B2="Real",B2="DInt",B2="DWord"),"DB1,DBD"&INT(C2),"??"))))
    1. 按 WinCC 变量表的列顺序整理好“名称、数据类型、地址”，复制后在 WinCC 变量表最下面空行的第一格 Ctrl + V。粘不进去的话，先从变量管理导出一份 Excel 看格式，填好再导入。
    2. 抽查几个，特别是 Real 和 Bool。
    Bool 要用 TEXT(C2,"0.0")，否则 Excel 会把 0.0 变成 0。出现 ?? 的是 String、数组、Struct 等，单独处理。
第六阶段

做测试画面并激活

WinCC 按需通信

画面上的控件要读哪个变量，WinCC 才去连那个变量所属的连接。画面上没有控件引用新连接下的变量（比如 I/O 域里的变量名是手敲的、敲错了，或者引用的还是旧驱动下的变量），WinCC 就根本不会去连 NetToPLCsim。所以测试时用 I/O 域，变量一律从列表里选。

  1. 新建测试画面

    项目管理器 → 右键 图形编辑器 → 新建画面 → 右键新画面 → 重命名 为 ConnTest.Pdl → 双击打开。已有项目也新建一个，不动原画面。

  2. 放 I/O 域并绑定变量

    1. 右侧 对象选项板（没有的话 视图›工具栏 勾出来）→ 标准 → 智能对象 → I/O 域，拖到画面上。
    2. 弹出组态对话框：变量 点右边的选变量按钮，在列表里展开到 SIMATIC S7 Protocol Suite›TCP/IP›PLC_1214C，选变量，不要手工输入。
    3. 更新 选 500 ms，域类型 选 I/O 域（能显示也能输入）→ 确定。
    4. 每个测试变量放一个 I/O 域，旁边放一个 静态文本 写上变量名。
    已画好的 I/O 域不用重画：右键 → 组态对话框，或 属性›输出/输入›输出值 灯泡图标上右键 → 变量，重新选变量即可，灯泡变绿说明绑定成功。Real 想显示小数，把 输出格式 改成 999.99。

  3. （可选）放一个点动按钮

    1. 对象选项板 → 窗口对象 → 按钮，拖到画面上，文本填 启动。
    2. 右键按钮 → 属性 → 事件 选项卡 → 左边 按钮›鼠标。
    3. 按左键 那一行的闪电图标上右键 → 直接连接：左边“来源”选 常数 填 1，右边“目标”选 变量 选一个 Bool 变量 → 确定，闪电变蓝。
    4. 释放左键 同样设置，常数填 0。
    点动要用“按左键 / 释放左键”两个事件。“鼠标动作”是点一下才触发一次，只能写一个值。

  4. 设为启动画面并激活

    1. 图形编辑器 Ctrl + S 保存。
    2. 项目管理器 → 图形编辑器 → 右键 ConnTest.Pdl → 定义画面为启动画面。
    3. 左边 计算机 → 右边计算机 → 属性 → 启动 页确认勾选了“图形运行系统”。
    4. 确认 PLCSIM 是 RUN、NetToPLCsim 是 running，点工具栏 ▶ 激活。
    测试通过后，记得把启动画面改回原项目的主画面。
验证

三层判断是否真的连上

从粗到细，三层都过了才算完全连通。

  1. netstat：WinCC 有没有发起连接

    netstat -ano | findstr :102
    看到的说明
    LISTENING 之外还有 ESTABLISHEDWinCC 已经通过 TCP 连上 NetToPLCsim
    只有 LISTENINGWinCC 没发起连接：画面没引用新连接的变量、连接建在了错误的通道单元、或访问点选成了 ISO

  2. 驱动程序连接状态：S7 通信是否建立

    WinCC 项目管理器 工具›驱动程序连接状态，看 PLC_1214C 那一行：正常 且读写计数在涨就是通了。旧驱动的连接一直显示断开，不用管。

  3. 双向改值：地址是否正确

    博图打开 DB → 点 全部监视（眼镜图标）。

    • PLC → WinCC：博图里右键变量 → 修改操作数，改成 123，画面上的 I/O 域 1 秒内跟着变。
    • WinCC → PLC：在 I/O 域里输入 456 并按回车，博图监视值跟着变；按住按钮，Bool 变 TRUE，松开变 FALSE。
    现象说明
    两边一致完全连通，地址也对，可以批量建变量了
    连接正常，但值一直是 0、改了也不变PUT/GET 没勾、DB 还是优化块、或者只下了软件没下硬件配置
    Int 对，Real 是离谱的大数Real 的 WinCC 数据类型选错
    改 A，WinCC 里却是 B 在变；或前面的对、后面的错偏移量算错，重点查数组 / Struct 的偶数字节对齐
    能读不能写访问级别不是完全访问，或控件是“输出域”而不是“I/O 域”
日常使用

每次联调的启动顺序

  1. 博图 V16：开始仿真 → 下载 → RUN

    PLC 程序有修改时重新下载；改了 DB 结构的话，WinCC 里对应变量的地址也要按新的偏移量更新。

  2. NetToPLCsim：管理员运行 → 停服务选“是” → Start Server

    必须在 PLCSIM 已经运行之后再启动，否则找不到仿真 PLC。每次重启电脑后都要重新打开，被停掉的服务也会恢复，会再问一次。

  3. WinCC V7.5：激活运行

    关闭时反过来：先退出 WinCC 运行，再停 NetToPLCsim，最后关 PLCSIM。

联调前

检查清单

  • 博图

  • 博图 V16、S7-PLCSIM V16、WinCC V7.5 已安装且有授权，NetToPLCsim 已解压
  • 1214C 固件版本为 V4.0 及以上

  • 硬件配置和程序都已下载到 PLCSIM，PLCSIM 处于 RUN

  • 网络与 NetToPLCsim

  • 环回网卡 IP 为 192.168.0.10，与真实网卡不在同一网段
  • NetToPLCsim 以管理员运行，站点为 192.168.0.10 → 192.168.0.1，机架 0 插槽 1，已 Start Server
  • Test-NetConnection 192.168.0.10 -Port 102 结果为 True

  • WinCC

  • 项目里的计算机名与 %COMPUTERNAME% 一致，当前用户在 SIMATIC HMI 组
  • 设置 PG/PC 接口中 CP-TCPIP 指向“环回适配器.TCPIP.1”
