WinCC 怎么和博图连接

从零讲清楚：WinCC 有哪几种、它们和博图是什么关系，以及每种情况下从建项目到画面显示 PLC 数据的完整步骤，包括没有真实 PLC、博图和 WinCC 都装在同一台电脑上时怎么用仿真联调。最后附排错表和上线检查清单。菜单名以中文版博图为准，括号里给出英文版的叫法。

先确定你属于哪种情况

情况 A · 最常见 WinCC 装在博图里面 触摸屏（KTP/TP 面板），或电脑上跑 WinCC RT Advanced / Professional / Unified。画面就在博图项目里做。 情况 B · 有真实 PLC 单独安装的 WinCC V7 / V8 连真实 PLC PLC 程序在博图里写，画面在独立的 WinCC 项目管理器里做，电脑通过网线连现场 PLC。 情况 C · 无硬件 博图和 WinCC 都在本机，用仿真联调 没有真实 PLC，程序在博图里写，画面在独立 WinCC 里做，用 PLCSIM Advanced 在同一台电脑上模拟 PLC。 情况 D 用 OPC UA 通用连接 S7-1500 / 新固件 S7-1200 自带 OPC UA 服务器，任何支持 OPC UA 的上位机都能连。
前置概念

“WinCC” 其实是几个产品

名字是什么和博图的关系
博图 TIA Portal西门子的集成开发平台。STEP 7 写 PLC 程序，WinCC 做画面，都在这一个软件里开发平台本身
WinCC (TIA Portal)
Basic / Comfort / Advanced / Professional / Unified		装进博图里的 HMI 组态软件，版本越高支持的设备和功能越多在博图内部，PLC 和画面放在同一个项目里
WinCC V7.x / V8（俗称经典版）独立安装的 SCADA（监控与数据采集）软件，适合大型上位机系统在博图外部，只能通过网络通信访问 PLC
为什么要分清

同一个博图项目里，博图知道 PLC 的 IP 地址、变量名和数据块结构，所以 HMI 能直接浏览 PLC 变量，连接也能自动生成。经典版 WinCC 是另一个软件，打不开博图项目，只能按 IP 地址去访问 PLC，所以通信驱动、变量地址、PLC 的访问权限都得自己配置。

通信的本质

不管哪种情况，HMI 和 PLC 之间都是一根以太网线（PROFINET 口），走西门子的 S7 通信协议，PLC 那边用 TCP 102 端口。HMI 每隔一个“采集周期”（默认 1 秒）问 PLC 要一次变量的值，按钮按下时把值写回 PLC。所谓“连接”，就是让 HMI 知道 PLC 的地址，并且知道每个变量在 PLC 里的位置。

情况 A

博图内部的 WinCC：PLC 与 HMI 同一项目

适用于精简面板 / 精智面板（Basic / Comfort），以及 PC 上的 WinCC RT Advanced / Professional / Unified。

  1. 确认 PLC 已在项目中，并设置好 IP

    在项目里双击 PLC 打开设备视图，点 PLC 的网口，进入 属性›常规›PROFINET 接口›以太网地址，设为 192.168.0.1 / 255.255.255.0。

  2. 添加 HMI 设备

    触摸屏：项目树›添加新设备 (Add new device)›HMI，选系列和尺寸，比如 SIMATIC 精简系列面板 → 7" → KTP700 Basic。订货号和版本号要和实物铭牌一致。

    电脑做上位机：添加新设备›PC 系统›常规 PC›PC station。然后打开它的设备视图，从右侧硬件目录拖入：

    • SIMATIC HMI 应用软件›WinCC RT Advanced（或 RT Professional）
    • 通信模块›PROFINET/Ethernet›常规 IE (IE general)，代表电脑的网卡
    添加触摸屏时如果弹出“HMI 设备向导”，在 PLC 连接 这一页直接选中你的 PLC，向导会自动建好连接，第 3 步就可以跳过。

  3. 在网络视图里连线、建 HMI 连接

    • 项目树双击 设备和网络 (Devices & networks)，切到 网络视图。
    • 从 PLC 的绿色 PROFINET 口拖一条线到 HMI（或 PC station 里常规 IE）的网口，两者会加入同一个子网 PN/IE_1。
    • 点工具栏的 连接 按钮，下拉选 HMI 连接，再从 HMI 拖到 PLC，生成 HMI_连接_1。
    • 点 HMI 的网口，把 IP 设为 192.168.0.2，掩码一致。
    检查方法：打开 HMI 设备›连接，表里应该有一行，伙伴是你的 PLC，状态没有红色报错。

  4. 在画面里绑定 PLC 变量

    • 打开 HMI›画面›根画面，从右侧工具箱拖一个 I/O 域 或 按钮。
    • I/O 域：属性›常规›过程›变量，点 “...”，直接浏览到 PLC 的变量表或 DB 块，选中变量。
    • 按钮：属性›事件›按下，加系统函数 置位位 (SetBit)，释放事件加 复位位 (ResetBit)，变量选 PLC 里的点动位。

    选中 PLC 变量后，博图会自动在 HMI 变量表里生成一个同名变量，“连接”一栏填好 HMI_连接_1。这种方式叫符号寻址（按变量名访问），所以 DB 块保持默认的“优化的块访问”就可以。

    注意：DB 块属性里的“可从 HMI/OPC UA 访问”（每个变量后面的勾）要保持勾选。取消勾选后 HMI 浏览不到这个变量。

  5. 编译并下载

    • 先选中 PLC → 编译 → 下载。
    • 触摸屏：先在面板上进入 Control Panel›Transfer 启用 PN/X1 传输，并在 Network Interface 里设好 IP。然后在博图里选中 HMI → 下载到设备。
    • PC station：电脑上打开 Station Configurator（站组态编辑器），把 WinCC RT 和网卡放到与博图相同的插槽号，站名也要一致；然后在博图里对 PC station 下载。

  6. 没有硬件时：用 PLCSIM 仿真联调

    • 选中 PLC → 开始仿真（会启动 S7-PLCSIM），下载程序并切到 RUN。
    • 选中 HMI → 右键 开始仿真›运行系统。
    • 画面上 I/O 域显示数值、按下按钮 PLC 变量跟着变，就说明通了。
    仿真显示 ####：打开控制面板里的“设置 PG/PC 接口”，把应用程序访问点 S7ONLINE 指向带 PLCSIM 字样的条目，重启 HMI 仿真。
情况 B

经典版 WinCC V7 / V8 连接真实的 S7-1200 / 1500

要做三件事：电脑网卡能到达 PLC，WinCC 有对应的通信驱动，PLC 允许被外部访问。

  1. 电脑网卡与 PLC 同网段

    给上位机网卡设一个静态 IP，比如 192.168.0.10 / 255.255.255.0。在命令行里 ping 192.168.0.1，能通再往下做。

  2. 设置 PG/PC 接口

    控制面板（或 WinCC 项目管理器里）打开 设置 PG/PC 接口 (Set PG/PC Interface)，访问点 S7ONLINE 选择接到 PLC 的那块网卡，条目名形如 Intel(R) Ethernet ... .TCPIP.1。

    电脑上有 WiFi、蓝牙、VMware 虚拟网卡时最容易选错，一定按网卡名称核对。

  3. 博图里设置 PLC 的访问权限

    双击 PLC → 属性›防护与安全 (Protection & Security)：

    • 访问级别：先选“完全访问权限（无任何保护）”调通，之后再按需加密码。
    • 连接机制 里勾选 允许来自远程对象的 PUT/GET 通信访问。用旧驱动或绝对地址时必须勾。

    改完后编译并下载到 PLC，硬件配置也要一起下载，只下程序不会生效。

  4. WinCC 里添加通信驱动和连接

    推荐（V7.4 SP1 及以上）：

    • WinCC 项目管理器 → 变量管理 → 右键 添加新的驱动程序 → SIMATIC S7-1200, S7-1500 Channel。
    • 展开到通道单元 OMS+ → 右键 新建连接，命名如 PLC_1。
    • 连接属性里填 PLC 的 IP 192.168.0.1，PLC 设了访问密码的话这里也要填。

    旧版本：驱动选 SIMATIC S7 Protocol Suite → 通道单元 TCP/IP → 新建连接，填 IP、机架号 0、插槽号 1（S7-300 是 2）。

  5. 创建变量：符号寻址或绝对寻址

    方式一：符号寻址（新驱动，推荐）

    • 在连接下打开 AS 符号 (AS Symbols)，选 从 AS 读取，WinCC 会在线从 PLC 拉取变量表和 DB 结构。
    • 勾选需要的变量，添加到 WinCC 变量管理。之后改了 PLC 程序，再读一次就能同步。
    • 按名字访问，DB 块可以保持“优化的块访问”。

    方式二：绝对寻址

    • 手动新建变量，地址写成 DB1.DBD0（双字）、DB1.DBX4.0（位）、M10.0、I0.0 这种形式。
    • 博图里对应 DB 块：右键 属性›属性 (Attributes)，取消勾选“优化的块访问”，编译后 DB 里会多出“偏移量”列，按这一列的地址填。
    为什么优化块不能用绝对地址

    “优化的块访问”打开后，PLC 会按自己的方式重新排列变量的存储位置，以换取更快的访问速度，所以变量没有固定的字节偏移量，DB1.DBD0 这样的地址也就不存在。符号寻址按名字找变量，不依赖偏移量，所以不受影响。

  6. 画面绑定变量并激活运行

    • 打开 图形编辑器 (Graphics Designer)，新建画面，放一个 I/O 域，组态对话框里选择刚才的变量，更新周期选 1 s 或 500 ms。
    • 项目管理器 → 计算机属性 → 启动，勾选“图形运行系统”，起始画面选这张画面。
    • 点工具栏的 ▶ 激活。回到变量管理，在变量上右键查看 连接状态，显示“正常”就算连好了。
手边没有真实 PLC、想在同一台电脑上联调，直接看下面的 情况 C。
情况 C

博图和 WinCC 都在本机：用 PLCSIM Advanced 仿真联调

没有真实 PLC，程序在博图里写，画面在独立的 WinCC V7 / V8 里做，三样东西都跑在同一台电脑上。

为什么普通 PLCSIM 不行

博图自带的 S7-PLCSIM 只和博图内部通信，不对外开放网络接口，单独安装的 WinCC 找不到它。S7-PLCSIM Advanced 会在电脑上装一块“虚拟网卡”，让仿真 PLC 拥有自己的 IP 地址。这样 WinCC 就能像连真实 PLC 一样，按 IP 去连它。

  1. 确认 PLC 型号

    PLCSIM Advanced 只支持 S7-1500 和 ET 200SP CPU，不支持 S7-1200。程序是 1200 的话，先看本节末尾的替代方案。

  2. 博图里打开“支持仿真”并放开访问权限

    • 右键项目名 → 属性›保护，勾选 块编译时支持仿真。不勾的话，下载到仿真器时会报错。
    • PLC 属性›防护与安全：访问级别选完全访问，勾选 PUT/GET。
    • 记下 PLC 的 IP，例如 192.168.0.1。

  3. 启动 PLCSIM Advanced 实例

    • 打开 S7-PLCSIM Advanced 控制面板。
    • Online Access 切到 PLCSIM Virtual Eth. Adapter。选成 “PLCSIM” 本地模式的话，博图能下载，WinCC 却连不上。
    • Instance name 随便填；IP 填 192.168.0.1（和博图一致）；Subnet 填 255.255.255.0；PLC type 选 Unspecified CPU 1500。
    • 点 Start，等实例指示灯变黄（STOP 状态）。

  4. 给虚拟网卡设 IP，确认能 ping 通

    安装 PLCSIM Advanced 后，网络适配器里会多出一块 Siemens PLCSIM Virtual Ethernet Adapter。给它设一个同网段的静态 IP，比如 192.168.0.10。cmd 里 ping 192.168.0.1 能通，说明仿真 PLC 已经在线了。

    如果本机的真实网卡也在 192.168.0.x 网段，两边会冲突。这时把仿真 PLC 和虚拟网卡一起改到 192.168.100.x 这类不冲突的网段，博图里的 PLC IP 也同步修改。

  5. 博图下载到仿真 PLC

    选中 PLC → 下载。PG/PC 接口类型选 PN/IE，接口选 Siemens PLCSIM Virtual Ethernet Adapter。搜索到 192.168.0.1 后下载，完成后切到 RUN。

  6. WinCC 连接仿真 PLC

    • 设置 PG/PC 接口：S7ONLINE 指向 Siemens PLCSIM Virtual Ethernet Adapter.TCPIP.1。
    • 变量管理 → 添加 SIMATIC S7-1200, S7-1500 Channel → OMS+ → 新建连接，IP 填 192.168.0.1。
    • 用 AS 符号 → 从 AS 读取 导入变量，或者按情况 B 的方式手动填绝对地址。
    • 画面绑定变量 → 激活运行，连接状态显示“正常”就通了。
别同时开两个仿真器：PLCSIM Advanced 和博图自带的普通 PLCSIM 会互相冲突，只保留一个。

情况 D

OPC UA 通用连接

适合跨厂商上位机，或者 WinCC 与 PLC 之间想用标准协议的场合。

  1. PLC 启用 OPC UA 服务器

    PLC 属性›OPC UA›服务器，勾选 激活 OPC UA 服务器。端点地址形如 opc.tcp://192.168.0.1:4840。

    同时在 运行系统许可证›OPC UA 里选择已购买的许可类型，否则编译会报错。

  2. 决定开放哪些变量

    默认 DB 和变量表里勾了“可从 HMI/OPC UA 访问”的变量都会出现在服务器的地址空间里。下载到 PLC。

  3. WinCC 作为 OPC UA 客户端连接

    • 经典 WinCC：变量管理 → 添加驱动 OPC UA WinCC Channel → 新建连接，填端点地址，浏览并导入变量。
    • 第一次连接时，客户端和服务器需要互相信任对方的证书。调试阶段可以先选安全策略 None，跑通后再改为 Sign & Encrypt 并互相导入证书。
补充

把经典 WinCC 的画面搬进博图

两种 WinCC 的画面格式不同，不能直接复制粘贴。官方方法是在原电脑上用 SIMATIC Migration Tool 把 WinCC V7 项目导出为迁移文件，再在博图里 项目›移植项目 (Migrate project)，目标是 WinCC Professional。图形对象和变量大多能转过来，VBS / C 脚本和部分 ActiveX 控件要手动重写。老的 WinCC flexible 项目可以直接在博图中打开移植。

上线前

检查清单

  • PLC 和 HMI / 上位机的 IP 前三段相同，子网掩码一致，能互相 ping 通
  • 博图里 HMI 连接存在，伙伴是正确的 PLC（情况 A）
  • PG/PC 接口 S7ONLINE 指向正确网卡（情况 B，或仿真时指向 PLCSIM）
  • 用绝对地址时已勾 PUT/GET，相关 DB 已取消优化块访问，并重新下载了硬件配置
  • 用符号寻址时，需要的变量都勾了“可从 HMI/OPC UA 访问”
  • 本机仿真时：PLCSIM Advanced 用 Virtual Eth. Adapter 模式，虚拟网卡与仿真 PLC 同网段，且没有同时打开普通 PLCSIM
  • Windows 防火墙已放行 TCP 102（OPC UA 是 4840）
  • WinCC 运行系统授权有效，不在演示模式
  • 采集周期按需要设置，变量很多时不要全设成 100 ms，以免通信负载过高
适用版本参考：博图 V16 至 V19 / V20，WinCC V7.4 SP1 及以上 / V8。不同版本的菜单位置可能略有差异，以实际软件为准。
