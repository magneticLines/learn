灌装项目拆解：这套程序在控制什么

other/ 目录下有两个西门子项目：灌装/ 是博图项目，Canned/ 是 WinCC 项目。这一页根据项目文件里能读出来的变量、程序块、画面脚本和硬件型号，还原整套项目的设计。

一句话结论

这是一个教学用的“液体灌装生产线”仿真项目。传送带带着瓶子依次经过称重吹气、灌装、拧盖、贴标、热缩包装、清洗、消毒七个工位。PLC 程序负责按顺序控制每个工位的气缸、阀门和电机。因为手边没有真实设备，程序里还写了一套“仿真数据”，计算瓶子位置、气缸行程、灌装液位和各工序进度，交给 WinCC 画面做成会动的动画。

分析方法和可信度

博图和 WinCC 的项目文件都是二进制格式，没有安装软件就无法直接打开。不过这些文件里会以文本形式保存变量名、注释、块名、画面脚本等信息，把这些文本提取出来对照着看，就能还原出项目的大致结构。

可信度：变量名、硬件型号、DB 偏移量是直接读出来的。梯形图网络在项目文件里是 zlib 压缩的 XML，解压后再和每个块的操作数表（按“网络号 + 元件编号”）对上，就还原出了每个网络的逻辑，所以下文关于程序的描述都来自实际程序。少数常量和定时器参数没有完全解出，以博图中实际打开的程序为准。

名词解释

DC/DC/DC：三个 DC 依次表示供电电源、数字量输入、数字量输出都是直流 24 V。输出是晶体管，开关速度快，但只能带直流负载。另一种型号 AC/DC/RLY 用交流供电、继电器输出。

模拟量：数字量只有开和关两种状态，模拟量是一个连续变化的值，比如液位 0～100%。传感器输出 4～20 mA 或 0～10 V 的电信号，模块把它转换成 0～27648 的整数交给 PLC，程序再把这个整数换算成实际的液位、重量。

同一个项目里有两套 HMI：博图里的 TP700 触摸屏，和独立的 WinCC V7.5。真实产线上，触摸屏通常装在设备旁边给操作工用，WinCC 装在中控室电脑上做集中监控。这里大概率是课程要求两种都练一遍。
02

工艺流程：七个工位

传送带把空瓶依次送到每个工位，到位传感器检测到瓶子后，传送带停下，工位动作，完成后传送带继续走。

工位顺序已从程序里的仿真网络确认：瓶子先在第一排（罐子.Y = 0）依次经过称重吹气（X=150）、灌装（X=340）、拧盖（X=530），走到头后换到第二排（Y=200），再依次经过标签投放（X=150）、包装热缩（X=250）、清洗（X=400）、消毒（X=530）。所以标签投放的到位信号虽然是 I1.0，在流程里排第四。
工位做什么执行器反馈 / 检测完成标志

为什么气缸要两个限位

气缸是用压缩空气推动活塞做直线运动的执行器，相当于一只“只会伸和缩的手臂”。PLC 打开电磁阀，气缸开始伸出，但 PLC 并不知道它什么时候伸到底。所以在行程两端各装一个磁性开关：碰到下限位说明已经压到瓶子上，可以开始灌装或拧盖；碰到上限位说明已经安全抬起，传送带才能继续走。没有上限位就开动传送带，灌装头会撞到瓶子，这是顺序控制里最基本的互锁。

I/O 分配：每个点接的是什么

I/O 指 PLC 的输入（Input，接按钮和传感器）和输出（Output，接指示灯、阀门、电机）。I0.2 表示输入字节 0 的第 2 位，对应 CPU 上一个具体的接线端子。

1214C 本体有 14 个数字量输入（I0.0～I1.5）和 10 个数字量输出（Q0.0～Q1.1）。表里用到的 I2.x、Q2.x 超出了本体范围，说明还扩展了一块数字量模块或信号板，订货号没能从文件里确认，需要在博图的设备视图里看。
M0.x 和 M1.x 是时钟 / 系统存储器

项目里用到了 M0.0～M0.7 和 M1.0～M1.3，刚好对应 1200 的两个默认功能：时钟存储器 MB0（8 个不同频率的方波，常用来让指示灯闪烁）和系统存储器 MB1（M1.0 首次扫描、M1.2 常 1、M1.3 常 0）。程序里实际用到的是 Clock_10Hz（M0.0）和 Clock_5Hz（M0.1）的上升沿，作为仿真动画的节拍：每 0.1 秒让坐标、行程、进度加一次；以及 AlwaysTRUE（M1.2）。

04

程序结构：四个程序块 + 一个数据块

程序用梯形图（LAD）编写，按功能拆成编号的块，Main（OB1）每个扫描周期依次调用它们。

块职责（从还原的梯形图得出）
01系统启停启动、停止、复位的逻辑。物理按钮（I0.0/I0.1/I2.1）和 HMI 按钮（DB.HMI按键.启动 等）是“或”的关系，任意一个都能启停。输出运行指示灯 Q0.0。
02模拟量处理把 IW30/IW32 的原始整数换算成实际重量和液位，写入 检测数据.称重实际值 / 液位实际值。DB 里的 转换值[0..1]、中间值[0..1] 两个数组，就是博图常用两步换算的中间结果：NORM_X 把 0～27648 归一化成 0.0～1.0，SCALE_X 再缩放到实际量程（重量 0～2000，液位 0～100）。第 3 个网络按 仿真开关 决定实际值取真实读数还是仿真值。
03自动控制部分真正的顺序控制都在这里，共 11 个网络：称重吹气、灌装、拧盖、标签投放、包装热缩、清洗、消毒各一个，传送带控制一个，还有一个“仿真”网络用比较指令代替传感器（如 罐子.Y = 0 且 罐子.X = 150 时把 I0.2 置 1）。传送带的条件是：每到一个工位就停，等该工位的“完成”标志置位后再走。
04流程只负责显示：运行中哪个执行器在动作（吹气阀门、灌装阀门、拧盖电机、标签投放、包装热缩、清洗机、消毒机），就把 状态.流程 写成 1～7；都不动作时写 0，复位时也清 0。画面用它显示当前工序。
吹气延时TON（接通延时定时器）的背景数据块，控制吹气持续多长时间。

所有 HMI 交互和中间数据都集中在一个全局 DB 里，分成六个部分：

P/N0.0Array[0..100] of Bool给上升沿 / 下降沿指令（P、N 触点）存上一周期状态用

为什么这样分组

按数据流向分组：HMI 写给 PLC 的放一组（按键、设定），PLC 写给 HMI 的放一组（检测、状态、仿真）。好处是排查问题时一眼就知道该去哪边找：按钮按了没反应，就查“HMI按键”有没有变成 1；数值显示不对，就查“检测数据”。这和 Java 里把 Request DTO 和 Response DTO 分开写是同一个思路。

DB 的 Offsets 里同时有 stdSize 和 optSize 两套偏移：前者是“非优化访问”的固定字节偏移，后者是“优化访问”的。WinCC 用 DB1,DBX48.0 这种地址读写，依赖的就是前一套。这就是联调教程里要求取消优化块访问的原因。
05

仿真机制：没有真设备，画面怎么动起来

真实产线上，瓶子在传送带上移动，到位后触发传感器，PLC 读到输入信号才继续下一步。仿真时没有瓶子也没有传感器，这个项目的做法是在 PLC 里用数据“演”出整条线：

  1. 传送带运行时，仿真数据里的坐标递增

    仿真数据.传送带、罐子.X / 罐子.Y 不断累加，代表瓶子在画面上的位置。

  2. 坐标到达某个值，相当于“到达工位”

    03自动控制部分 的仿真网络用比较指令把坐标换算成到位信号，直接写进 I0.2～I1.0 这些输入点；气缸行程为 0 就是上限位，到最大值就是下限位。传送带看到到位信号就停。

  3. 工位动作时，行程和进度递增

    吹气.气缸、灌装.气缸、拧盖.气缸 从 0 增大，表示气缸往下伸；灌装.液位、拧盖进度、热缩进度 等从 0 涨到目标值，表示工序在进行。

  4. 到达目标值后置位完成标志，流程步号加一

    状态.完成灌装 等置 1，04流程 推进到下一步，传送带重新启动。

“仿真瓶子质量过低 / 超重”按钮

没有真实称重传感器时，称重值永远是正常的，异常分支永远测不到。所以画面上做了两个开关按钮，按下后 PLC 把称重仿真值改成低于下限或高于上限的数值，触发“瓶子异常示灯”。这是测试异常分支的常用手法，类似 Java 单元测试里用 Mock 返回异常数据。

仿真数据.仿真开关 是总开关（02模拟量处理 第 3 个网络）：为 TRUE 时液位、重量用仿真值，为 FALSE 时用模拟量模块的真实读数。仿真时必须为 TRUE，否则液位一直是 0，灌装工位会卡住。
06

WinCC 画面做了什么

主画面是 罐装.Pdl，里面用 VBS 动态化脚本把仿真数据绑定到图形的位置属性上，每个周期刷新一次（下面是去掉函数外壳后的简化写法）：

' Bottle moves horizontally with the conveyor
矩形1.Left = SmartTags("DB_仿真数据_罐子_X") + 145
矩形1.Top  = SmartTags("DB_仿真数据_罐子_Y") + 176

' Cylinders move down as stroke value grows
控件4.Top = SmartTags("DB_仿真数据_吹气_气缸") + 80
控件5.Top = SmartTags("DB_仿真数据_灌装_气缸") + 50
控件6.Top = SmartTags("DB_仿真数据_拧盖_气缸") + 58

' Label drops onto the bottle
控件7.Top  = SmartTags("DB_仿真数据_标签投放_标签Y") + 114
控件7.Left = SmartTags("DB_仿真数据_罐子_X") + 150

后面加的常数（145、176、80……）是图形在画面上的初始坐标，PLC 只负责给出“偏移了多少”，两边各管各的。

版本痕迹和疑点

项目文件里残留了一些旧版本的名字，能看出这个项目改过几轮：

痕迹说明
到达灌装位置1 / 2、灌装1气缸、灌装2_液位早期有两个灌装工位，后来合并成一个。WinCC 画面脚本里还在引用 到达灌装位置1/2，激活后这两个变量会找不到。
罐装.Pdl 和 罐装1.Pdl两份画面，罐装1 可能是旧版本的备份，正式使用的是 罐装.Pdl。
WinCC 变量 DB_设定数据_罐装1质量博图 DB 里已经没有这个成员，同样是双灌装工位时期留下的。
WinCC 变量地址形如 0001:TS:0:...原来用的是 S7-1200/1500 Channel 按符号访问，所以才需要整理 wincc-tag-mapping.csv，迁移到 S7 Protocol Suite 的绝对地址。
映射表里“液位检测、称重检测”找不到项目数据里能看到这两个变量（Int，模拟量输入，对应 %IW30、%IW32 附近）。可能是在 PLC 变量表的另一张表里，而不是默认变量表。
