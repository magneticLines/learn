W22 · 阶段 3 · 核心节点

Daily standup 与进度汇报：30 秒把事说清

阶段 3 从这里开始，因为它是频率最高、模板性最强、见效最快的场景 —— 每天一次，结构固定，练两周就能从"打草稿念"变成"张嘴就说"。而且它是你在团队里最频繁的英语曝光，改善会被立刻注意到。

PART 1 学习资料 读完再动手 · 约 20 分钟

先看常见的失败方式

反例 · 中文母语者的典型 standup

Yesterday I do the... the API thing. I meet some problem about the database. Today I will continue. That's all.

问题：时态错、动词形式错、信息含糊（什么 problem？continue 什么？）、没有 blocker 意识、结尾生硬

正例

Yesterday I finished the retry logic for the payment API. I ran into an issue with connection pooling — it's not blocking me yet, but I might need Dave's input later today. Today I'm picking up the integration tests. That's it from me.

同样 30 秒，信息量高得多，而且主动标记了潜在 blocker

关键洞察：standup 讲不好，八成不是英语问题，是信息结构问题。

你用中文开 standup 也可能说得很含糊 —— 只是中文含糊时你能靠语速和补充糊过去，英文含糊就暴露了。

所以本节的一半内容是结构（说什么、什么顺序、什么颗粒度），另一半才是语言（句式和语块）。先解决结构，语言问题会小一半。

三段结构，固定顺序

段内容时长关键
① 昨天完成了什么（结果，不是过程）10 秒用完成态：finished / shipped / got X working
② 阻塞有没有 blocker，需要谁10 秒这一段最重要，很多人完全跳过
③ 今天要做什么（具体到可验证）10 秒用 I'm picking up / I'll be working on

注意顺序：阻塞放中间，不放最后。因为 standup 的核心目的就是暴露阻塞 —— 放最后容易被时间挤掉，或者你说完"今天要做什么"就自然停了。

核心句式与语块

① 昨天完成了什么

用法句式
完成了I finished / wrapped up / shipped the ...
基本完成I got the X working, still needs polishing.
做了但没完成I made progress on X — about halfway through.
方向变了I ended up going a different route on X because ...
花了很久X took longer than I expected.

避免只说 I worked on X —— 这句话零信息量，母语者会追问。要给结果或进度。

② 阻塞与求助（本节最该练的部分）

强度句式
没有阻塞No blockers. / Nothing blocking me.
潜在阻塞Not blocked yet, but I might need X.
已阻塞I'm blocked on X. / I'm stuck on the ...
需要人I could use a hand with ... / I need to sync with Dave on ...
等外部I'm waiting on the API keys from the platform team.
要拉会Can we take this offline after standup?

Can we take this offline? 是 standup 里最有用的一句话 —— standup 不是讨论会，遇到需要深聊的事就用它把话题挪走。会用这一句，你就不会被卷进十分钟的即兴技术讨论。

③ 今天要做什么

Today I'm picking up ... / I'll be working on ... / My plan is to get X done by EOD. / I'm going to focus on ...

④ 收尾

That's it from me. / That's all from my side. / Yeah, that's me.

不要说 That's all.（有点生硬，像宣布结束）或 Over.（像无线电通话）。That's it from me. 是最标准的说法。

时态：本节唯一的语法重点

standup 的语法需求很窄，只有三个时态，但正好都是中文母语者的雷区：

段落时态例子常见错误
昨天过去式I finished ...I finish ...（词尾 -ed 没发出来，见 W5）
现在的状态现在完成 / 进行I've been looking into ...误用一般现在时
今天将来 / 现在进行表将来I'm picking up ...I will do ...（太生硬，母语者少用）

第三行值得注意：表达"今天打算做"，母语者更常用现在进行时（I'm picking up X）而不是 I will do X。后者听起来像临时决定或承诺，前者听起来是已排好的计划。

时态错在 standup 里格外显眼。因为整个 standup 就是在区分"做完的 / 正在做的 / 要做的"—— 时态承载的正是这个核心信息。

而且很多人的时态"错误"其实是语音问题：finished 的 /t/ 没发出来（W5 的词尾辅音）。先检查嘴，再检查语法（W20 讲过这个判断方法）。

两周练成的具体方法

  • 第 1–3 天：写 + 念。把 standup 写成稿，出声念，录音。允许打稿——这几天目的是建立结构和句式
  • 第 4–7 天：只写关键词。三段各写 2–3 个关键词，其余现场生成（这是 W16 复述的合规笔记规则）
  • 第 8–10 天：不打稿，直接说。录音，和第 1 天的录音对比
  • 第 11–14 天：加压。让 AI 在你说完后追问细节（真实 standup 里会发生），练"被追问后继续说"
  • 全程：每天录音存档。十四天的录音串起来听，是你能拿到的最直观的进步证据

常见陷阱

  • 只说过程不说结果。I worked on the API 零信息量。说结果或进度百分比。
  • 跳过 blocker 那一段。最常见也最有代价 —— standup 的核心目的就是暴露阻塞。没阻塞也要明确说 "No blockers"，那是一个信号，不是省略。
  • 说太细。standup 不是技术评审。细节留到 offline，用 Can we take this offline? 挪走。
  • 被卷进即兴讨论。有人接话开始讨论技术细节，十分钟过去了。会用那一句 offline 就能收住。
  • 时态混乱。本节唯一的语法重点。先检查是不是词尾辅音没发出来。
  • 每天照念同一份稿。会念得很流畅，但那是朗读能力，不是口语能力。三天后必须切到关键词模式。
  • 因为怕说错而说得极短。Yesterday API. Today tests. No blockers. —— 语法上安全，但你在团队里的存在感也一起消失了。宁可有错，也要有信息。

操练型 P2 · 每日实战（连续 14 天）
本节主力，每天用一次。用你真实的工作内容，不要虚构——真实内容才会遇到真实的表达困难。每天两分钟，十四天后对比第一天的录音。
你是我的英语 standup 教练。我要连续练 14 天，每天两分钟。

我的情况：中文母语者、软件工程师。
我的重点问题：时态（尤其 -ed 词尾）、说得含糊、跳过 blocker。

【今天是第 __ 天】（我每次会更新这个数字，你根据阶段调整要求）

阶段规则：
- 第 1–3 天：我可以打草稿。你的重点是帮我把结构和句式搭对
- 第 4–7 天：我只写关键词。你要检查我是不是在念稿（念稿的特征是过于流畅、

【我今天的真实工作内容】（中文，我每天填）

【你的任务】

操练型 P3 · 被追问训练
真实 standup 里说完常会被追问，而这才是真正考验的部分——准备好的 30 秒你能说，追问就露馅了。这个练习也顺带练澄清策略和卡壳急救。
你是我的英语 standup 教练。本次专项：**被追问后的应对**。

背景：我准备好的 30 秒 standup 能说得不错，但一被追问细节就崩。真实 standup 里追问很常见。

【训练设定】
1. 我先说一段 standup（我会给我的真实工作内容，或你给我一个虚构场景）
2. **你必须追问**，每轮 2–3 个问题，轮换以下追问类型：
   - 要具体数字（多久？多少个？什么时候能完成？）
   - 要技术细节（具体怎么做的？为什么选这个方案？）
   - 质疑判断（为什么这个优先？确定这样行吗？）
   - 追问阻塞（具体卡在哪？需要谁？为什么现在才说？）
   - 追问风险（这会不会影响发布？有没有 plan B？）
   - **突然换话题**（问我另一个不相关的任务进度）
3. 语速正常偏快，不要照顾我
4. 如果我回答含糊（it depends / maybe / some issues），继续追问，不接受

【你的评估维度】
每轮结束后：
1. 我有没有直接回答问题？还是绕开了
2. 我有没有用澄清策略确认问题（如果我没听懂）
3. 我卡壳时怎么处理的：沉默 / 蹦中文 / 填充撑住 / 成功绕过
4. 我给的信息够不够具体
5. 我有没有在压力下时态崩掉
6. **如果我不知道答案，我的处理方式对不对？**
   （给我几个"我不知道但显得专业"的说法，如
    "I don't have that number off the top of my head — let me check and get back to you"）

【四轮场景，压力递增】
第一轮：友好的同事随口问细节
第二轮：技术负责人追问技术选型依据
第三轮：项目经理追问时间和风险，有明显的进度压力
第四轮：多人追问 —— 你扮演 2–3 个人轮流问，中间不给我喘息

【四轮后总评】
1. 我的追问应对能力评估
2. 哪类追问最让我崩（数字？技术细节？质疑？换话题？）
3. 我不知道答案时的处理是否得体
4. 一份「被追问急救句式」清单：10 个，覆盖
   争取时间 / 承认不知道 / 稍后回复 / 请求具体化问题 / 转给别人
5. 下次重点

要求：全程英文对话，评估用中文。不要心软，不要接受含糊回答。

【第 14 天的 standup 转写】
【中间的错误记录】（如果有，每天的时态错误次数等）

请做对比分析：

1. 【结构对比】
   - 三段结构的完整度：第 1 天 vs 第 14 天
   - blocker 那一段有没有从"跳过"变成"主动说"
   - 顺序和时间分配

2. 【信息量对比】
   - "零信息量表达"的数量变化

   - 母语者听完会追问的点，数量变化

3. 【语言对比】

   - 时态错误次数（特别是 -ed / -s 词尾）

   - 用词的地道程度

4. 【流畅度对比】
   - 卡顿次数、沉默次数

5. 【是真进步还是只是熟悉？】（关键判断）
   明确回答：改善主要来自
   (a) 表达能力真的提升了，还是
   (b) 我把这套 standup 说熟了？
   判断方法：**给我一个全新的、我没准备过的工作内容场景，让我立刻说一段 standup**，
   然后评估这段新内容的表现。如果新内容也说得好，是 (a)；如果明显退回第 1 天水平，是 (b)。

6. 【剩余问题】
   还有哪些问题没解决？按优先级排序，不超过 5 条。

7. 【下一步】
   - standup 这个场景算不算过关了？过关标准是什么
   - 我该进入下一个场景（code review）还是继续巩固
   - 如果进入下一个场景，standup 该以什么频率维持
