口语篇：让意思清楚到达对方

这是"进入表达"的第一课，也是 26–38 所有口语课的总地图。核心结论：口语不是一场独自完成的发音表演，而是两个人一起完成一件事。目标不是"消灭口音、不再停顿"，而是对方听懂了主线、记住了关键细节、知道下一步做什么；出错以后，你们还能一起修复回来。

PART 1 学习资料 读完再动手 · 约 35 分钟

先纠正一个默认假设：口语不是考试，是协作

很多人（包括 up 原作者自己）一开始把口语想成一场临场考试：开口前先在脑子里把句子排好，发音要像录音里的人，停顿最好没有，错误不能被听见。结果是 —— 越想说好，开口前的门槛越高，越不敢开口。

但真实的对话不是你一个人的独白。对方会追问、会误解、会补充、会突然换话题，还带着自己的口音、语速、耳机质量和背景噪音。所以口语能力不只住在"发音"里，它至少还包括：

  • 能不能先把主线说出来（而不是绕半天才进正题）
  • 能不能察觉对方没跟上
  • 能不能换一种说法再讲一次
  • 能不能承认暂时不知道，而不是硬编
  • 修复一次误解之后，能不能继续把事情做完
程序员类比：口语更像一次网络通信，而不是一次本地函数调用。

本地函数调用：你写好参数，调用，拿到结果，全程可控 —— 这是你想象中的口语。
网络通信：会丢包、会乱序、对端可能是不同版本的协议实现。好的通信系统不是"永不丢包"，而是有 ACK 确认、有重传、有超时处理。

所以本章衡量口语的标准是：消息最终是否完整到达，以及丢包后你有没有重传机制，而不是你的发送端"长得像不像"某个标准实现。

§1 先把"提高口语"改写成一个具体任务

"我要提高口语"和"我要提高系统性能"一样 —— 太大了，没法直接优化。做性能优化前你一定会先问：哪个接口？P99 要降到多少？在什么并发下测？口语也一样，要先把它改写成一个会真实发生的动作：

任务类型练习条件完成证据（怎么算"做到了"）
说明60–120 秒，无稿讲一段经历、观点或流程听众能复述主旨 + 两个关键细节
问答至少 5 轮，包含 1 个事先不知道的追问没有完全答偏，并主动推进了一次对话
修复故意保留一次没听清、范围不明或说崩的时刻双方通过重复、确认或换说法恢复了共同理解
协作会议、面试、客户沟通或一起做决定对方知道结论、分歧、负责人、下一步
迁移换主题 / 换听众 / 换设备 / 加时间压力不靠原稿仍然能完成相近任务

开始任何一次练习前，先写三句话：谁在听？为什么听？听完以后对方需要知道或做什么？这三句就是你这次练习的"验收标准"。

把录音、听众复述、修复动作和延迟复测放在一处，可以用工具箱里的 口语证据卡。

§2 保存三种"未经修饰"的基线

为什么要三种？因为口语能力不是一个数字，而是几个互相独立的维度。有人独白很流利，一被追问就乱；有人发音很清楚，却听不出对方到底在问什么。只测一种，就会漏掉另外的短板（回想 04 三条独立通道：不同能力要分开测）。

  1. 独白基线：无稿说 90–120 秒，讲一个真实经历或问题
  2. 互动基线：完成 5 轮问答，其中 1 题事先未知
  3. 修复基线：录下一次"请对方重复 / 确认范围 / 换说法 / 总结共识"的过程
"未经修饰"是这一步的关键。不降噪、不剪掉停顿、不让 AI 先帮你改稿再念。

类比：做性能优化前跑 benchmark，你不会先把慢请求从数据里删掉再算平均值。基线一旦被"美化"，后面所有对比都失真。

同时要记录测试条件：用什么设备、网络如何、是否看了提纲、是否允许重录、听众是否熟悉这个话题。条件不同的两次录音，就像在不同机器上跑的 benchmark，不能直接比较。

录完后，请一位听众只根据录音回答下面四个问题（不给他看文字稿）：

你听到的主旨是什么：
哪两个细节最清楚：
哪里需要猜测或重听：
你接下来会问什么或做什么：

为什么先听、不先看转写稿？因为转写稿能暴露用词和句子结构，却丢掉了重音、停顿、语气和接话时机 —— 这些恰恰是口语独有、写作里没有的信息。详细的回听方法见 10 录音自查。

§3 选一个参考变体，但不制造"高低等级"

英语有地区、社群、职业和个人的差异。美式和英式只是两个常见的"入口"，不是全部英语，也没有谁比谁高级。

那为什么还要"选一个"？为了减少初期的决策成本。同一个词，先跟一套可靠音频练；同一份正式文本，保持一种拼写。选择时看四件事：

考虑因素要问自己的问题
真实受众我主要面对哪类同事、客户、考官、社区？
稳定材料词典音频、课程、反馈者能不能长期保持一致？
任务成本拼写、词汇、发音差异真的影响我现在的交付吗？
个人身份我愿意长期用这种声音说话吗？还是在把自己藏进模仿里？
误区 · "选一种"变成"只有一种正确"

只听美音材料，听到印度同事、新加坡客户就懵

把对方的口音当成"不标准"，把自己的口音当成"错误"

结果：输出单一、输入也单一，真实协作里两头吃亏

正解 · 一致性服务学习，耐受度服务现实

自己说的时候跟一套参考音频，保持稳定

自己听的时候逐步加入印度、新加坡、尼日利亚、英美等多种口音

结果：说得稳，也听得广

类比：团队选一份代码风格规范（比如 Google Java Style），是为了自己写的代码一致；但你仍然要能读懂开源项目里各种风格的代码。规范约束的是你的输出，不是你能理解的范围。可以给自己写下两条边界：

当前参考变体：
选择它因为：
我需要逐步听懂的其他变体：
哪些差异只需识别，不必强迫自己模仿：

§4 把三个概念拆开：口音显著度 ≠ 可理解度 ≠ 理解难度

这是本章最重要的一个区分，也是最多人混淆的地方。

概念它指什么怎么观察
口音显著度
accentedness		听者觉得你的声音和他熟悉的参照差多少只能说明"听起来不同"，不能单独证明任务失败
可理解度
intelligibility		听者实际恢复了多少词、主旨和关系让听众复述主旨、细节、数字、负责人、下一步
理解难度
comprehensibility		听者为了听懂要付出多少努力是否需要重听、猜测、暂停、多次确认
用代码来理解这三者：

口音显著度 ≈ 代码风格和你习惯的不一样（比如对方用 tab 缩进、大括号换行）。看着别扭，但不影响运行。
可理解度 ≈ 代码的功能是否正确 —— 测试能不能通过。
理解难度 ≈ 代码的可读性成本 —— Reviewer 要读几遍才看懂。

一段代码可以风格很"另类"但功能正确、也好读；也可以格式完全符合规范，却因为逻辑混乱让人看不懂。口语同理：口音明显但很容易懂的人很多；听起来很"标准"但数字、重点、逻辑关系不清的人也很多 —— 后者才真正阻断了任务。

还要注意：听者也会带着经验、偏见和熟悉度进入判断。一个从没接触过中文口音的人，第一次听你说话可能费劲，这不全是你的问题。所以不要把一次负面反馈全部归因于自己。更可靠的判断来自多个条件：至少两位听众、不同设备，或者换一个新主题；同时记下他们听见了什么，而不只是"像不像母语者"这种评价。

§5 发音训练：先修"高影响"的问题

音标是地图，不是终点。它帮你定位口形、舌位、气流、声带振不振动，但不能替代可靠音频、你自己的录音和真实听众。

发音问题要像 bug 一样分级：P0 是改变意思、导致误解的；P3 是音色上的细微差异。永远先修 P0。

① 音与词义：只练会造成误解的那几对

比如 /ɪ/ 与 /iː/（ship / sheep）、/r/ 与 /l/、清辅音与浊辅音 —— 它们重不重要，由你自己的词汇、受众和错误记录决定，不必把 44 个音平均刷一遍。系统讲解见 13 元音与 schwa、14 辅音痛点。

练一对音用五步：

  1. 听辨两个词，确认你能分清
  2. 观察口腔动作（镜子或视频）
  3. 慢速说
  4. 放回短句里说
  5. 在陌生句子里再次选对

如果单词能说对、放进句子就消失了 —— 说明问题已经不在单音，而在节奏或调用，要转去练句子层面。

② 词尾、重音与边界：它们携带关键信息

work / worked              ← 时间：现在还是过去
fifteen / fifty            ← 数字：差了 35
REcord / reCORD            ← 词性：名词还是动词
We need the BLUE file.  /  We NEED the blue file.   ← 句子重点不同

不要只问"每个音准不准"，要问：听众有没有听出过去时、数字、关键词和对比？一个轻微的音色偏差，优先级通常远低于丢掉 -ed 或者把重音放错。对程序员来说，fifteen 和 fifty 在汇报"15 分钟 / 50 分钟宕机"时可是事故级的差别。深入见 15 单词重音、16 句子重音与意群；技术词的读法见 26 程序员术语发音。

③ 句块、停顿与语气：帮听者预测结构

把长句按意思切成可呼吸的块：背景、主张、理由、条件、下一步。停顿放在关系之间，而不是随机切断一个词组：

Based on the current test, / I recommend a smaller release, / because rollback is still available.

节奏不是为了表演"地道"，而是给听者结构提示 —— 就像代码里的空行和缩进，让人一眼看出哪里是一个逻辑块。先让主线清楚，再去加连读、弱读、语调这些细节（17 连读、18 弱读与缩合、19 失爆与同化、20 语调）。

§6 跟读不是终点：从模仿走向生成

跟读（shadowing）能帮你观察声音、节奏和停顿。但是跟读时，内容、词序、下一句说什么，全都由别人决定了。它就像照着教程一行一行敲代码 —— 能练手速和语法感，但不能证明你能独立写出一个新功能。

所以同一段材料，要走完五级：

级别做什么练的是
1 · 听与标记写下主旨、重音、停顿、没听清的位置输入
2 · 朗读看着文本说清楚，不急着复制所有细节声音
3 · 延迟跟读和原音保持短暂距离，观察节奏，不抢速度节奏模仿（27 影子跟读）
4 · 合上复述保留意思，用自己的词序说生成（28 复述）
5 · 陌生追问回答材料里没有预先提供答案的问题迁移
陷阱：第 4 级崩了，就回去无限加跟读次数。

这是在用"多读几遍教程"解决"不会独立写"的问题，方向错了。正确做法是：缩短材料、减少信息点，从"只记住三个关键词，然后自己组织"开始重新练。

§7 用词块建立"可变的支架"

口语确实需要一些能快速调用的结构（原理见 07 语块：工作记忆有限，按块调用才有余量想内容）。但背完整稿件会把流畅锁死在固定条件里 —— 题目一变就失效。更有用的是可替换的词块：

The main issue is ...
What changed was ...
I am not certain about ..., but the current evidence suggests ...
Could we first clarify ...?
My recommendation is ..., because ...

每个词块至少做三种变化：换主题、换立场、换听众。再加一个意外条件："对方不同意""数据不完整""只剩 30 秒"。

背整稿 · 硬编码

像把配置写死在代码里：String host = "10.0.0.1";

环境一换（话题、听众、追问一变）就崩

可替换词块 · 模板 + 参数

像 String.format("My recommendation is %s, because %s", a, b)

骨架固定、内容随场景填，同一个模板能服务几十种情况

词块是脚手架，不是面具。目标不是随时说出同一句话，而是借它先把主线立起来，再根据对方的反应改下一句。按功能整理好的词块地图见 29 功能句式地图。

§8 互动修复不是补救，而是一项能力

对话中出现误解一点也不异常。真正异常的是：双方已经失去共同理解，却因为怕暴露问题，硬着头皮继续往下说。

回到网络类比：TCP 的可靠性不是来自"永不丢包"，而是来自 ACK、重传、窗口控制。修复动作就是你口语里的可靠性协议。五类修复：

情况修复动作示例
没听清请求重复或放慢Could you say the last part again?
范围不明确认问题Are you asking about the cause or the next step?
需要思考争取有限的时间Let me think for a moment.
表达失败换一种说法Let me put that another way.
共识不稳总结并请对方确认So we will test it today and decide tomorrow. Is that right?

不要只背这些句子。让同伴故意说快、中途改问题、误解一个数字、追问证据，观察你能不能发现断点并把任务拉回来。自己说卡住的急救手段见 30 卡壳急救；听不懂对方时的确认技巧见 31 澄清策略。如果你的目标是海外求职或远程协作，后面"进入岗位"一组会把项目说明、陌生追问、承认未知放进同一个场景。

§9 自己、真实听众、教师、AI 怎么分工

角色适合做什么不能单独证明什么
自己保存原始录音、标停顿、比较版本你太熟悉自己的声音，会自动脑补听众没听见的信息
真实听众复述主旨、指出要猜的地方、继续行动一位听众可能受熟悉度和偏见影响
教师 / 教练观察口腔动作、节奏、可教的问题、训练顺序反馈仍要回到你的任务和迁移样本去验证
AI / 语音识别候选转写、生成追问、定位可能不清的片段识别结果受口音、麦克风、噪声、模型、网络影响
陷阱：把语音识别的分数当成"发音真相"。

ASR 没认出你的词，可能是你的问题，也可能是麦克风、背景噪音或模型训练数据的问题 —— 就像单元测试挂了，不一定是被测代码错，也可能是测试环境坏了。

向 AI 要反馈时：先交任务和你自己的第一版，再要求它区分可能听错 / 明确听错 / 组织问题 / 语法问题 / 语域选择 / 风格偏好。保留原始音频和工具版本。AI 陪练的具体用法见 42 AI 口语陪练。

隐私边界：涉及客户、同事、学生、家人、医疗或未公开项目的录音，上传前先取得许可；否则用虚构信息或本地处理。练习的价值不能建立在越过别人隐私边界之上。

§10 把练习放回生活

低压力的练习有它的位置：朗读一段喜欢的文字、给朋友留一条英文语音、跟着一首歌唱、用英语讲今天真实发生的小事。它们不能替代问答和修复，但能让声音离开脑内审查、进入身体。关键是让轻松练习和真实任务连起来：从歌词里取一个词块，第二天用进自己的句子；从语音留言进入一次追问；从朗读进入合上材料后的复述。兴趣负责让你回来，证据负责告诉你是否前进。

生活与社交里的具体场景已经拆成了单独的课：32 出行链路、33 住与吃、34 应急与求助、35 Small Talk、36 讲故事与观点、37 礼貌层级与文化差异。

一个 12 分钟闭环，每天都能做：

  • 2 分钟　无稿说首版（录音）
  • 3 分钟　回听，只标记一个高影响问题
  • 3 分钟　针对它做发音、词块或修复练习
  • 2 分钟　重录
  • 2 分钟　回答一个陌生追问，写下下次要换的变量

§11 十四天口语实验

十四天不是"口语速成期"。它只回答一个很小的问题：在没有熟悉稿件、换了听众、出现追问之后，这项表达还能不能用？全程只追踪一个真实场景和少量高影响问题。

天动作留下的证据
1定义一个真实场景，录独白 + 五轮问答原始录音、条件、听众复述
2选择参考变体与可靠音频选择理由、不必模仿的差异
3找一个高影响发音或节奏问题错误片段 + 它对任务的影响
4听辨 → 慢说 → 短句 → 陌生句四种条件的录音
5同一材料：朗读、延迟跟读、合上复述模仿与生成的差异
6建立 5 个可替换词块三种主题变式
7撤掉原稿，第一次延迟复测新主题 90–120 秒录音
8让同伴制造一次没听清或范围不明修复过程与确认结果
9更换听众或设备条件变化后的听众复述
10听一种不熟悉的英语变体并复述主旨、细节、不确定点
11只修仍然反复出现的一项问题第三版 + 被拒绝的低影响建议
12让 AI / 同伴提三个陌生追问无稿回答 + 转写误差
13在时间压力下完成协作或决策说明结论、负责人、下一步
14关闭提示，完成新场景，决定下一轮保留 / 调整 / 转向的依据

§12 怎么判断口语正在变成能力

  • 听众一次就能复述主旨和关键细节
  • 数字、时间、负责人、条件、下一步更少被误解
  • 出现停顿或错误后能继续，而不是退出对话
  • 能主动确认问题、请求重复、换说法、总结共识
  • 七天后撤掉原稿，仍能组织相近任务
  • 换主题、听众、设备或口音后仍能完成（深度迁移见 38 复杂话题深聊）
  • 能区分：必须修的问题 / 参考变体差异 / 身份偏好
  • 对 AI、教师或听众的反馈，能说出采纳和拒绝的理由

流畅不是单位时间里塞进更多词，也不是把停顿全部剪掉。它是注意力逐渐从"我听起来够不够像别人"转回到"我们是否还在理解同一件事"。

常见陷阱

  • 把"消灭口音"当目标。投入巨大、回报很低，还会让你更不敢开口。目标是可理解度，不是口音显著度。
  • 只录背过的稿子。背稿测的是记忆，不是口语。基线必须无稿、未修饰。
  • 只问"我说得怎么样"。得到的只有"挺好的"。要问"你听到了什么"，让对方复述。
  • 平均用力刷所有音。先修会改变意思的 P0 问题（数字、词尾、重音），音色细节最后再说。
  • 无限跟读。跟读 50 遍也不会自动变成能独立生成。第 4、5 级才是口语。
  • 一次修十个问题。每轮只修 1–3 个，否则哪个也没真正修好，也分不清是哪个改动起了作用（和一次 commit 只做一件事是同一个道理）。
  • 怕暴露没听懂而硬接话。这是最危险的：共同理解早已断开，后面越聊越偏。修复是能力，不是丢脸。
  • 只用一个听众、一种条件下的结果下结论。至少换一个听众或设备再判断。

来源与边界

  • Derwing & Munro (2005), Second Language Accent and Pronunciation Teaching —— 区分口音与沟通结果，强调相互可理解性，同时提醒口音具有社会影响。
  • Levis (2005), Changing Contexts and Shifting Paradigms in Pronunciation Teaching —— 讨论发音教学从"减少口音"转向可理解度、身份、世界英语与说听双方协商。
  • Saito (2012), Effects of Instruction on L2 Pronunciation Development —— 综合 15 项准实验干预研究；群体平均结果不等于对个人的效果保证。
  • 发音、词汇、语域和可接受性会随地区、社群、任务和听众变化。重要交付应结合当前受众、可靠词典音频、专业反馈与真实任务复测。
PART 2 AI 提示词 点右侧按钮复制 ·
本节的 AI 分工：AI 在口语里能做的是模拟听众、制造追问和干扰、定位可能的高影响问题；它不能替你说，也不能单独证明你的发音好坏。

四条铁律：① 先保存自己的无稿首版录音/转写，再找 AI；② AI 只做支架（诊断、追问、操练），不代写稿子让你背；③ 要求 AI 标出"不确定"——尤其是它基于转写推断发音时；④ 最后关掉 AI，在新话题上独立复测。

使用顺序：P1 诊断首版（模拟听众复述）→ P2 讲清你的高影响发音问题 → P3 从跟读走到陌生追问 → P4 互动修复干扰训练 → P5 七天后延迟复测。
诊断型 P1 · 模拟听众：先复述，再诊断
不要问"我说得好不好"，而是让 AI 先扮演听众复述它听到了什么，再按影响分级。注意转写稿本身可能有识别误差，所以要求它把"可能是识别错"和"明确是表达问题"分开。
你是一位英语口语教练，同时扮演一名不熟悉我工作背景的听众。

背景：我是中文母语者、软件工程师。下面是我一段【无稿、未修改】口语录音的语音识别转写。
转写可能有识别错误，请不要把识别错误直接当成我的发音错误。

【任务定义】
谁在听：
为什么听：
听完对方需要知道或做什么：

【录音条件】
设备 / 是否看提纲 / 是否重录过 / 时长：

【我的转写】
（粘贴，保留 um、uh、重复和自我修正，不要清理）

请按顺序输出：

一、听众复述（只根据转写，不脑补）
- 你听到的主旨是什么
- 哪两个细节最清楚
- 哪里需要猜测
- 你接下来会问什么或做什么

二、问题分类（每条都标注置信度 高/中/低）
- 可能是识别错误（建议我回听原音确认）
- 明确的表达组织问题（主线不清、重点后置、缺下一步）
- 可能影响理解的发音线索（如数字、词尾 -ed/-s 疑似丢失、关键词被识别成别的词）
- 语法问题
- 语域选择
- 纯风格偏好（不必修）

三、本轮只修的 1–3 个高影响问题
按"对任务的影响"排序，说明为什么它比其他问题更重要。
明确列出你建议我暂时忽略的低影响问题。

四、不确定之处
哪些判断你只能靠转写推测、必须由真人听众或原音确认？

规则：不要重写我的整段话给我背。可以给出某一句的 1–2 种改法作为参考，但必须说明改动理由。
讲解型 P2 · 我的高影响发音问题：讲清原理 + 五步练法
把 P1 或真人听众找出的那一个问题交给 AI，让它讲清楚为什么会错、怎么练。重点是让它基于你的真实词汇出题，而不是给一份通用音标表。
你是一位英语语音教师，熟悉中文母语者的常见发音迁移问题。

我的参考变体：（如 General American / 英式 / 暂未确定）
我的主要受众：（如 印度和美国同事、欧洲客户）

【我反复出现的问题】
（例：fifteen 和 fifty 被同事听混；worked 的 -ed 常被听成 work；REcord/reCORD 不分）

【出现的真实句子】
（粘贴 2–3 句原话）

请：
1. 用小白能懂的方式解释：这个问题在发音上到底差在哪（口形、舌位、气流、声带、重音、时长），
   以及为什么中文母语者容易这样说。
2. 说明它对我的任务的影响等级：会不会改变词义、时间、数字、责任或句子重点？
   如果其实影响很小，请直接告诉我可以降低优先级。
3. 按五步给我练习材料，全部用我工作中的词：
   ① 听辨：5 组对比词（告诉我去哪类词典音频里听）
   ② 观察：口腔动作要点
   ③ 慢说：我要注意的 1 个关键动作
   ④ 短句：5 个含目标音的工作短句
   ⑤ 陌生句：5 个我没见过的句子，用来检查能否迁移
4. 如果单词能说对、句子里仍然消失，说明问题转到了哪一层（节奏？调用？），下一步该练什么。
5. 标出你不确定的地方：比如某个音在不同变体里本来就不同，属于"变体差异"而不是错误。

不要给我一张完整的 44 音表。只围绕这一个问题。
操练型 P3 · 从跟读到生成：合上材料 + 陌生追问
对应 §6 五级阶梯的第 4、5 级。跟读做完以后，用这个提示词检验你能不能脱离原文生成。如果第 4 级崩了，AI 会帮你缩短材料而不是让你回去多读。
你是我的英语口语陪练。我刚完成了一段材料的听、朗读和延迟跟读，现在要检验我能否脱离原文生成。

【材料主题和要点】（我只给你要点，不给原文，避免你变成提词器）
主题：
要点 1：
要点 2：
要点 3：

训练流程（严格按顺序）：
第 1 步 · 合上复述：请我用自己的词序复述这段材料，60–90 秒。
  我说完后，你只做三件事：
  - 列出我保留了哪些要点、漏了哪些
  - 指出我是否在背原文句子（如果几乎逐字，说明这还是模仿不是生成）
  - 指出 1 个最影响理解的问题
第 2 步 · 陌生追问：问我 3 个材料里没有直接答案的问题，一次一个，等我回答再问下一个。
  问题类型依次为：举一个我自己的例子 / 如果条件变了会怎样 / 我同意还是不同意，为什么。
  每题我回答后，你只用一句话指出：是否答偏、是否推进了对话。
第 3 步 · 结算：
  - 我在哪一级开始吃力（复述还是追问）
  - 如果复述就崩：把材料缩到 3 个关键词，给我一个更短的版本重新练
  - 本次可以入库的 3 个可替换词块（每个给换主题/换立场/换听众三种变式）
  - 你不确定的判断（例如只看转写无法判断的停顿与重音）

规则：全程英文对话，结算用中文。你每次最多说 3 句。不要替我说出答案，也不要因为我卡住就降低问题难度，最多给我一个开头词块。
操练型 P4 · 互动修复：让 AI 故意制造断点
修复句背得再熟，不在真实断点上用一次就不算会。这个提示词让 AI 故意说快、换问题、误解数字，逼你发现断点并把对话拉回来。
你扮演我的一位海外同事，我们在讨论一个真实的工作问题。本次训练目标：练习"互动修复"，而不是练流利。

场景：（例：线上事故复盘 / 需求范围确认 / 发布时间协商）
我的角色和立场：

请在对话中至少制造以下 5 种断点，但不要提前告诉我是哪一种，也不要按固定顺序：
1. 一句话说得很长很快，里面藏一个关键信息
2. 问一个范围模糊的问题（例如分不清是问原因还是问下一步）
3. 故意误解我说的一个数字或时间
4. 追问我一个我大概率不知道的证据
5. 在讨论结束前不明确下一步，看我会不会主动总结

我需要用的修复动作包括：请求重复、确认问题范围、争取思考时间、换一种说法、总结并请确认、承认不知道并给出跟进方式。

规则：
- 全程英文，你每次最多 3 句，像真实同事一样说话，不要放慢。
- 如果我没发现断点、硬接话，不要当场提醒，继续往下（就像真实会议那样）。
- 我说 "wrap up" 时用中文输出：
  · 你制造的每个断点：我发现了没有、用了什么修复动作、是否恢复了共同理解
  · 我错过的断点，以及当时可以说的 1–2 句修复语
  · 我有没有"假装听懂"的时刻
  · 最终双方对结论、负责人、下一步是否一致
  · 你不确定的地方（例如仅凭文字无法判断我的语气是否合适）

现在用英文开始对话。
抽查型 P5 · 七天后延迟复测：撤掉原稿、换话题
修好旧样本不等于能力留下了。七天后不看任何笔记，在一个相近但新的话题上做一次，对比基线。这一步之后最好再找一位真人听众复述一次，AI 的结论只作参考。
你是一位严格的口语测评者。这是一次延迟复测，用来检查我 7 天前练过的能力是否迁移，而不是复习旧材料。

【7 天前的基线信息】
场景：
当时找到的 1–3 个高影响问题：
当时练过的可替换词块：

测试流程：
1. 给我一个与原场景相近但没练过的新话题（不要提示词块，不要给提纲）。
2. 我无稿说 90–120 秒，然后你问我 2 个陌生追问，一次一个。
3. 我会把转写粘给你（含 um/uh 和自我修正）。

评估输出（中文）：
- 听众复述：主旨 + 两个细节 + 需要猜测之处
- 旧问题逐项判定：已消失 / 减少 / 仍在 / 无法从转写判断（必须给出依据）
- 词块是否在新话题里被自然调用，还是又回到了中式直译
- 追问中：是否答偏、是否主动确认或修复
- 和基线相比的结论：保留 / 调整 / 转向，三选一，并说明理由
- 你不确定、必须由真人听众或原音确认的判断

规则：测试过程中不给任何提示和点评，只说 "Noted."。不要因为我卡住而降低难度。
